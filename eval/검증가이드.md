## 0. 준비 (한 번만)

### GitHub
1. 재윤님이 보낸 **저장소 초대 메일**을 열어 수락합니다. (저장소: https://github.com/jae-yoonlee/su_sibop)
2. 프로그램 설치
   - **GitHub Desktop** (https://desktop.github.com) — 명령어 없이 쓸 수 있어 추천합니다.
   - 최신 **Chrome** 또는 **Edge** (AI 측정은 이 둘에서만 됩니다).
   - 5번 작업(기준값 수정)을 직접 돌려 보려면 **Node.js 22** (https://nodejs.org). 1~4번만 하면 필요 없습니다.
3. GitHub Desktop → File → Clone repository → `jae-yoonlee/su_sibop` 선택 → 내 PC에 받기.

### 작업할 때마다 (규칙)
1. GitHub Desktop 위쪽 **Fetch origin** → **Pull** (최신으로 맞추기).
2. **Current branch → New branch** 로 내 브랜치를 만듭니다. 이름은 `yeojin/작업이름` (예: `yeojin/model-eval`).
   - `main`에 바로 올리지 않습니다. main에 들어가면 바로 사이트에 배포되기 때문입니다.
3. 파일을 바꾸거나 추가하면, 왼쪽 아래에 무엇을 했는지 한 줄 적고 **Commit** → **Push origin**.
4. **Create Pull Request** 버튼 → GitHub 웹에서 설명을 적고 PR을 만듭니다. 재윤님(또는 Claude)이 확인하고 합칩니다.

### 절대 올리면 안 되는 것 (저장소가 공개입니다)
- 실제 자소서, 실제 사람의 녹음·얼굴 영상, Gemini 키 같은 비밀번호.
- 이런 파일은 `data/private/` 폴더에만 두세요. 이 폴더는 GitHub에 올라가지 않게 막혀 있습니다.
- 녹화 영상은 올리지 말고, **영상에서 뽑은 숫자 표만** 올립니다.

## 2. 정답 라벨 따로 붙이기 (왜 필요한가)

검증 페이지의 "역량 찾기" 점수는 **자료를 만든 쪽(Claude)이 붙인 정답**과 비교한 값입니다. 만든 사람이 정답까지 붙이면 점수가 한쪽으로 치우칠 수 있어서, **여진님이 정답을 보지 않고 따로** 붙인 뒤 두 정답이 얼마나 일치하는지 봅니다. 발표에서 "정답의 신뢰도"를 말할 수 있게 됩니다.

1. `data/eval/라벨지.csv`를 엑셀로 엽니다. (`cases.json`의 labels는 **보지 마세요**.)
2. 자소서마다 10개 역량 칸에 **근거가 분명히 있으면 1, 없으면 0**을 적습니다.
   - 판단 기준: "면접관이 이 문장을 근거로 그 역량을 물어볼 수 있다"면 1.
   - 기간·역할·프로젝트 이름 칸도 자소서에서 그대로 옮겨 적습니다. (4단계 사실 대조의 정답이 됩니다.)
3. **다른 이름으로 저장 → CSV UTF-8** 형식으로 `data/eval/라벨지_여진.csv`에 저장해 PR로 올립니다.
4. 두 정답의 일치도(카파 계수)는 Claude가 계산해 드립니다.

## 3. 질문 모델 측정

### 무엇을 비교하나
| 후보 | 왜 넣었나 |
|---|---|
| 규칙 질문 | AI가 없을 때 쓰는 기준선. AI가 이것보다 나아야 의미가 있음 |
| Qwen3-1.7B | 지금 앱 기본값 |
| Qwen3.5-2B | 같은 크기대의 새 세대. 바꿀 1순위 후보 |
| Qwen3-0.6B / Qwen3.5-0.8B | 저사양 PC용 후보 |
| Qwen3-4B | 품질 상한. 이게 압도적이면 "큰 모델이 필요하다"는 근거 |

### 순서
1. 고사양 PC의 Chrome에서 https://jae-yoonlee.github.io/su_sibop/eval.html 을 엽니다.
2. "이 PC" 칸에 그래픽 정보가 나오는지 확인합니다. "그래픽 가속 없음"이면 그 PC로는 AI 측정을 못 합니다.
3. **1차: 품질 비교**
   - 모델 5개 모두 체크, 자소서 **20**개, 자소서마다 **1**번 → **측정 시작**.
   - 모델마다 처음엔 1~3GB를 내려받습니다. 와이파이에서, 탭을 앞에 띄워 두고 기다리세요. 중간에 탭을 닫으면 처음부터 다시 해야 합니다.
4. 끝나면 버튼 4개를 모두 눌러 내려받습니다: **요약 CSV, 사람 채점지 CSV, 채점 정답 키 CSV, 전체 원본 JSON**.
5. **2차: 같은 입력에 답이 흔들리는지** — 1차에서 좋았던 모델 2개만 체크, 자소서 **5**개, **3**번.
6. **3차: 속도** — 중간·저사양 PC에서 Qwen3-1.7B와 Qwen3.5-2B만, 자소서 5개, 1번. (속도는 PC마다 다르므로 표에 PC를 꼭 같이 적습니다. 요약 CSV에 자동으로 들어갑니다.)
7. 파일을 `eval/results/날짜_PC이름/` 폴더에 넣고 PR로 올립니다.

### 요약 표 읽는 법
| 열 | 뜻 | 좋은 값 |
|---|---|---|
| JSON 성공 | AI가 정해진 형식으로 답했나 | 100%에 가까울수록 |
| AI 질문 채택 | 질문 3개 중 검사를 통과해 앱에서 실제로 쓰였을 비율 | 높을수록 |
| 근거 문장 정확 복사 | AI가 "자소서의 이 문장 때문에 묻는다"고 낸 문장이 자소서에 글자 그대로 있는 비율. 낮으면 AI가 문장을 지어낸 것 | 높을수록 |
| 생성 시간 / 60초 안 | 앱은 60초 안에 질문이 안 나오면 규칙 질문으로 넘어감 | 60초 안 90% 이상 |
| 불러오기 | 모델을 띄우는 데 걸린 시간 (두 번째부터는 캐시라 빨라짐) | 참고 |

## 4. 질문 사람 채점

자동 지표는 "형식이 맞나"만 봅니다. **질문이 좋은지는 사람이 봐야** 합니다.

1. **사람 채점지 CSV**를 엑셀로 엽니다. 모델 이름은 숨겨져 있고 순서도 섞여 있습니다. (어느 모델인지 알면 무의식적으로 점수가 달라지기 때문입니다.)
2. 질문마다 세 칸에 1~5점을 적습니다. 옆에 자소서를 띄워 놓고(`cases.json`이나 검증 페이지) 보세요.

| 점수 | 구체성 | 자소서 연결 | 자연스러움 |
|---|---|---|---|
| 5 | 답할 때 기간·역할·결과 수치를 말하게 만드는 질문 | 자소서의 특정 경험을 정확히 짚음 | 실제 면접관이 그대로 말할 법함 |
| 3 | 방향은 있지만 "구체적으로"가 약함 | 자소서와 관련은 있지만 어느 경험인지 모호 | 뜻은 통하지만 어색한 표현 1~2곳 |
| 1 | "본인에 대해 말해 주세요" 수준 | 자소서와 무관하거나 없는 경험을 지어냄 | 문법이 틀리거나 질문이 아님 |

3. **한 명 더** (지인 1명) 같은 파일을 따로 채점하게 합니다. 서로 점수를 보지 않습니다. 두 사람 점수가 비슷해야 "채점이 믿을 만하다"고 말할 수 있습니다.
4. 각자 **CSV UTF-8**로 저장 → 검증 페이지 ③에 채점 파일과 정답 키를 넣으면 모델별 평균이 나옵니다. 화면을 캡처하고 파일도 `eval/results/`에 올립니다.

### 미리 정한 판단 기준 (결과 보고 나서 바꾸지 않기)
- 지금 기본값(Qwen3-1.7B)을 **바꾸는 조건**: 후보가 ① 세 점수 평균이 0.3점 이상 높고 ② AI 질문 채택이 10%p 이상 높거나 비슷하며 ③ 중간 사양 PC에서 60초 안 90% 이상.
- AI가 규칙 질문보다 평균 0.5점 이상 높지 않으면, "AI 질문이 꼭 필요한가"를 발표에서 솔직히 다룹니다.

## 5. 실시간 알림 기준값 확인 (녹화)

`webapp/src/rules/constants.ts`에서 `[가설]`이라고 적힌 값 5개(눈동자 흔들림, 주변 소음 +10dB, 목소리 적정 범위, 앞뒤 이동 25%, 소음 측정 상한)가 대상입니다.

1. 본인 + 지인 4명 이상. 각자 앱으로 면접을 한 번 하면서, 답변 시간 동안 **정해진 행동을 정해진 순서로** 합니다.

| 구간 | 행동 | 나와야 하는 알림 |
|---|---|---|
| 0~10초 | 정면 보고 보통 크기로 말하기 | 없음 |
| 10~20초 | 고개를 옆으로 30° 돌린 채 말하기 | 고개 돌림 |
| 20~30초 | 눈동자만 좌우로 계속 움직이기 | 시선 흔들림 |
| 30~40초 | 의자를 뒤로 빼 멀어지기 | 자리 이동 |
| 40~50초 | 아주 작게 말하기 | 목소리 작음 |
| 50~60초 | 말 멈추기 (휴대폰으로 음악 틀기도 한 번) | 말 막힘 / 주변 소음 |

2. 결과 화면의 **결과 저장 (JSON)**을 누르면 `results[].log`에 알림 후보가 생긴 시각(`t`)과 이름(`name`)이 남습니다. 알림 간격 규칙 때문에 화면에 안 뜬 것도 `log`에는 남으니, **화면 말고 log로** 셉니다. 구간별로 **맞게 나옴 / 안 나옴 / 엉뚱하게 나옴**을 셉니다. (처음 한 번은 `t`가 답변 시작 기준인지 Claude에게 확인받으세요.)
3. 엉뚱하게 자주 나오는 알림은 기준을 느슨하게, 안 나오는 알림은 기준을 빡빡하게 바꿀 후보입니다. 숫자를 바꿀 땐 `constants.ts`의 해당 줄만 바꾸고, 주석의 `[가설]`을 `[측정: 5명, 정답률 x%]`처럼 바꿉니다.
4. 영상은 올리지 않습니다. 표와 JSON(얼굴·목소리 없음)만 올립니다.

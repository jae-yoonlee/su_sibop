## 2. 지금 기술이 최선인가 — 기술별 냉정한 평가

| 기술 | 지금 | 약점 (솔직하게) | 더 나은 대안 | 검증 방법 (데이터셋) |
|---|---|---|---|---|
| 고개 각도 | MediaPipe 변환 행렬 | 정확도를 잰 적 없음. 안경·조명·측면에서 오차 가능 | 대안보다 **검증**이 먼저. 대안 후보: 6DRepNet 등 전용 모델(무거움) | **BIWI Kinect Head Pose**, **AFLW2000-3D**로 각도 평균 오차(°) 측정 → 20° 기준이 오차보다 충분히 큰지 확인 |
| 눈동자 흔들림 | blendshape eyeLook* 표준편차 | 기준값 근거 없음. 웹캠 시선은 원래 부정확 | 사람마다 보정(세팅 때 4방향 보기) 후 비교 | **MPIIGaze**(웹캠 시선) + 우리 녹화 10명: "의도적으로 두리번" vs "정면" 구간 분류 정확도 |
| 말함 판정 | 음량(소음의 3배) | 시끄러우면 말로 착각 → 5초 침묵·작은 목소리 판정이 같이 무너짐 | **Silero VAD (웹, 약 2MB)** — 소음에 강함. 바꿀 가치 큼 | 한국어 음성(**AI Hub 회의·대화 음성**, **KsponSpeech**) + 소음(**MUSAN**, **DEMAND**)을 SNR 0/5/10dB로 섞어 말함 판정 정확도 비교 |
| 주변 소음 | 바닥 소음 +10dB | 숫자 근거 없음 | 위와 같음 | 같은 합성 데이터로 오경보율 측정 |
| 역량 찾기 | NCS 단어 사전 (어간 일치) | **표현이 다르면 놓침.** 실제로 "이탈률을 30% 줄였다"를 처음엔 못 잡았음 | **문장 임베딩 유사도** (transformers.js + multilingual-e5-small 또는 ko-sroberta, 약 100MB, 브라우저 안) — 단어가 달라도 뜻으로 매칭 | **NCS 직무기술서**로 사전 확장, 가짜 자소서 30개에 사람이 역량 라벨 → 사전 vs 임베딩 정밀도·재현율 |
| 질문 생성 | Qwen3-1.7B (WebLLM) | 한국어 품질 미확인, 첫 방문 약 1GB, 그래픽 메모리 약 2GB 필요 | **Kanana 1.5 2.1B**(카카오, 한국어 특화, 상업 가능) — 단, MLC 변환 직접 해야 함. EXAONE 4.0 1.2B는 비상업 라이선스 | 가짜 자소서 20개 × 모델 3개: ① 근거 문장 복사 성공률(자동), ② 질문 품질 5점 척도(사람 2명 + Gemini 채점), ③ 생성 시간(저사양·중간·고사양 PC) |
| 받아쓰기 (3단계) | 계획: Web Speech API | 음성이 Google로 감, Chrome 전용 | Whisper small(브라우저, 약 590MB)은 로컬이지만 실시간 아님 | **KsponSpeech 평가셋** 일부 + 우리 녹음으로 글자 오류율(CER) 비교 |
| 사실 대조 (4단계) | 계획: 정규식 + 사용자 선택 | 받아쓰기가 이름을 틀리면 거짓 불일치 | 이름류는 자모 단위 유사도로 "확인 필요" 처리 | 가짜 자소서 + 답변 녹음 20쌍, 사람이 정답 표시 → 정확도 |

**결론**
- **지금 바꿔야 할 것 1순위: 말함 판정 → Silero VAD.** 침묵·작은 목소리·소음 세 판정이 모두 여기에 기대고 있어서, 효과 대비 비용이 가장 좋습니다.
- **2순위: 역량 찾기에 임베딩 추가.** 단어 사전은 설명 가능성 때문에 유지하고, 놓친 것만 임베딩으로 보완.
- **모델 교체(Kanana)는 측정 후 결정.** 측정 없이 바꾸면 발표에서 "왜 이 모델?"에 답할 수 없습니다.
- MediaPipe는 바꿀 이유가 없고, **오차를 재서 기준값의 근거를 만드는 것**이 할 일입니다.
